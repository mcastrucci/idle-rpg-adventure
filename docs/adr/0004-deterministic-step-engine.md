# ADR-0004: Combat engine as a deterministic step function

- **Status:** Accepted
- **Date:** 2026-11-01

## Context
Live (interactive, manual inputs) and idle (batch, automated) must share one engine. Determinism enables replays, death
logs, audits, golden tests and precomputed idle.

## Decision
- API shape: `step(state, inputs, rng) → { state, events }`. Live feeds player inputs at tick boundaries; idle feeds
  inputs generated by automation rules. Same code path.
- Determinism rules (enforced by lint + tests):
  - Integer arithmetic only; percentages in basis points (1 bp = 0.01%). Integer division with explicit rounding.
  - No `Math.random`, `Date`, `performance.now`, or transcendental `Math.*` (`sin/exp/pow/log`) inside `sim`.
  - Seeded PRNG (PCG32 or equivalent) with **named sub-streams** (`combat`, `loot`, `encounters`, …).
  - Explicit ordering of actors and events (initiative desc, then actor ID asc). No reliance on incidental iteration
    order.
  - No I/O.
- Every persisted simulation stores `engineVersion` and `contentHash`.
- Golden replay tests in CI on two Node LTS versions.
- Pure at the boundary; internal mutation of a working copy is allowed.

## Consequences
- Bugs are reproducible from `(seed, inputs, engineVersion, contentHash)`.
- Formulas must be designed for integers (see `docs/spec/combat-engine.md`).
- Changing engine behaviour requires bumping `engineVersion`.

## Evidence (spike 1)
The step engine (`rpg-sim@1.1.0`) and the survival toy share the PCG32 streams of `engine/sim-core`; golden replays run on
Node 22 and 24 in CI (`.github/workflows/ci.yml`). Gaps still open: a 1,000-repeat hash test and a heap/GC measurement.
See the [spike report](../spikes/spike-1-sim.md).
