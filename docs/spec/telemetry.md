# Internal telemetry report

`docs/queries/telemetry.sql` is a read-only PostgreSQL report over existing domain rows. Use a read-only database role and run from the repository root with `psql -X -v ON_ERROR_STOP=1 -f docs/queries/telemetry.sql`. It contains independent sections `Q1`–`Q9`; output may contain internal account and actor identifiers and must remain internal. No client analytics endpoint or external analytics service is involved.

## Metric rules

- Q1 counts authenticated application socket connection intervals. The socket is accepted on all app screens, so these are not foreground, attention, or gameplay minutes. Reconnects are separate intervals. A still-open or crashed interval ends at `last_seen_at`; the report never adds time up to query time or a lease expiry. Account IDs are pseudonymous join keys to a character only where a domain relation exists.
- Q2 counts distinct persisted discoveries. The time-to-conquest proxy is from the first currently retained discovery timestamp to `rpg_completed_areas.completed_at` (the persisted completed-area timestamp). This is not time spent actively playing, and discovery rows may be cascaded when a character is deleted.
- Q3 uses expedition `starts_at_ms` and the actual terminal report `endsAtMs` for effective duration, not worker settlement delay. Only JSON-number version 1 `settled` reports whose end is within the stored start/planned bounds and with exactly one valid actor XP row are eligible. `escrow_returned`, unknown versions, running reports and malformed/missing/duplicate values are excluded or marked uncovered; `rate_covered` is always false rather than null for uncovered rows. Cancellation uses its persisted report cutoff. Zero or unknown durations are excluded from XP/hour and labeled. Gross XP earned and actual XP penalty loss are reported separately, with net as their difference. Q7 counts lifecycle states, cancellation and the actor-specific `xpPenaltyApplied` flag, which is a reported penalty application rather than an inferred death count. Q8 aggregates per-player idle rates and exposes included/excluded run counts.
- Q4 attributes live time to immutable `rpg_live_entries.area_id`, never mutable checkpoint JSON. It includes only closed instances and uses entry-to-close wall time (including the reconnect grace interval). The existence of an entry row is the post-migration 0007 instrumentation marker: live starts create it atomically with the instance. A missing XP-event row for such an entry is a known zero and remains in the denominator. Pre-0007 runs have no entry row and cannot be attributed; there is no backfill, so Q9 counts closed RPG participant instances with and without an entry and marks missing entries legacy/unattributed. New zero-event runs remain known zero because the entry row marks instrumentation. Entry and XP-event rows follow their live instance and can disappear when that instance is deleted. Q4 excludes zero/negative durations from reward totals and rates, exposing their count. XP events and death penalties are aggregated independently before joining to avoid fanout. Each actor contributes at most once per instance. Death XP loss is shown as a known penalty; absence of a death row means no recorded penalty, not proof of no loss.
- Q5 measures recorded successful entries after a durable conquest outbox event, separately for the conquered area and any area. This is a behavioral return proxy, not evidence that every conquest triggered an automatic repeat attempt or that the player was interested or motivated.
- Q6 counts successful, server-confirmed Region 2 live entries from immutable `rpg_live_entries.area_id`, grouped by actor with first/latest persisted start times. Its coverage label is `successful_instrumented_entries_only`: locked or failed starts and client-submitted IDs do not create persisted attempt rows and cannot be counted. An actor with no returned row has no observed successful instrumented R2 entry in the retained data; zero/unobserved activity does not prove lack of interest or that the feature is unavailable. The query does not inspect runtime capability and must be run against the matching deployed source/content revision. Do not create synthetic production events or infer rejected attempts.
- Q7 counts all expedition starts and lifecycle statuses, persisted cancellations, actor XP penalty application flags, and unsupported/recovery reports. It independently counts distinct terminal expeditions with a recorded owner death event in supported version 1 settled report segments. The death report coverage and unknown/recovery counts are shown separately; a death can have zero XP penalty, and an XP penalty flag is not a death count. No death is inferred from an unsuccessful outcome or positive XP loss.
- Q8 aggregates idle earned/lost/net XP per actor, area, and activity over covered positive effective durations. Each expedition ID contributes once, including distinct identical runs. It reports earned XP, penalty lost XP, net XP, covered duration and the number of covered and excluded/uncovered terminal runs; compare its gross and net hourly rates with Q4 only with the Q4 and Q8 coverage limits in view.
- Q9 counts closed RPG participant instances with and without a durable entry row. No area is guessed for the unattributed cohort. Its nonpositive duration count is explicit; Q4 excludes those durations from rate numerators and denominators.

## Concept success criteria mapping

| §16 criterion | Query/evidence | What the query cannot establish |
|---|---|---|
| 1. Exploring illustrated scenes is interesting | Q1 session intervals and Q2 discovery cadence are coarse usage proxies | Cannot measure interest, enjoyment, attention, or whether art caused behavior. Requires qualitative playtesting/review. |
| 2. Understands how to conquer a region | Q2 discovery totals and persisted conquest timestamp | Does not measure comprehension or explain failed attempts; requires observation/interviews. |
| 3. Unlocking idle feels important | Q2 conquest time; Q5 later live entry after conquest | Return is not perceived importance. Pair with qualitative review. |
| 4. Expeditions produce useful progression | Q3 per-run and Q7 lifecycle details; Q8 effective duration, XP earned/lost/net and per-player covered XP/hour | Does not establish usefulness or balance; legacy/unknown reports are excluded. Requires progression review/playtest. |
| 5. Returning to live offers a perceptible advantage | Q4 live XP/hour alongside Q8 idle XP/hour for comparable actors/areas | Proxies cannot establish perceptibility, skill, or causal advantage; compare cohorts carefully and conduct playtests. |
| 6. Second region motivates improvement | Q6 observed successful instrumented R2 entries | Entry counts establish use only; they cannot establish motivation, improvement, or lack of interest. Requires qualitative playtesting. |
| 7. Shared combat works in both modes | Q3/Q8 expedition outputs and Q4 live rewards/death records | Telemetry shows outcomes only. Code review must verify the shared engine is used in both modes. Co-op is phase 2 and is not claimed here. |
| 8. Architecture allows adding content without rewriting core | Q2 discovered-area coverage, Q3/Q8 expedition area/activity coverage, and Q4 live area coverage are operational proxies | Coverage can show content exercised, not architecture quality. Requires architecture/code review and evidence from adding content; telemetry is not proof. |

These extracts are descriptive, not causal experiments or balance decisions. Every rate must be read with its coverage counts and exclusions. Do not interpret usage as interest, motivation, comprehension, or enjoyment.
