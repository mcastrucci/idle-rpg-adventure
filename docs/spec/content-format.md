# Spec: Declarative Content Format

> Status: **Draft v0.1**. Decision: [ADR-0008](../adr/0008-declarative-content-pipeline.md),
> [ADR-0014](../adr/0014-tiled-scene-editor.md).

## 1. Layout

The world (areas, locations, routes) is the engine model of [`docs/engine/world-model.md`](../engine/world-model.md);
the compiler (`@engine/content-compiler`) assembles it from one collection directory per entity type. Game collections
live next to it in directories registered by the game plugin.

```
games/rpg/content/
  world/
    areas/<area_slug>.json                      # engine Area (area:…), lists its location IDs
    locations/<area_slug>/<location_slug>.json  # engine Location (loc:…) + RPG fields
    routes/<route_slug>.json                    # engine Route (route:…), e.g. hub portals
  scenes/<area_slug>/<location_slug>.tmj        # Tiled map: background image layer + object layers (ignored by the
  art/                                          #   JSON pass; source art, compressed variants generated by pipeline)
  enemies/*.json                                # RPG collections, registered by the RPG plugin
  skills/*.json
  items/*.json
  loot-tables/*.json
  encounter-tables/*.json
  resource-nodes/*.json
  idle-activities/*.json
  progression/xp-curve.json                     # the single XP curve, id "progression:xp_curve"
```

- A `.json` file holds one entity or an array of entities; subdirectories are free-form and file names never matter
  (only IDs do). A `.json` file outside every collection directory is an error.
- Locations are flat (one world-wide collection); an area owns the locations listed in its `locations` array.
- The exact game directories are defined by the game plugin; see the compiler README for the plugin interface.

## 2. IDs

- Namespaced, lowercase snake: `area:verdant_hollow`, `loc:verdant_hollow.old_well`, `route:sanctuary_to_verdant_hollow`, `enemy:thornback_boar`,
  `skill:cleave`, `item:minor_healing_potion`, `loot:boar_common`.
- Never renamed, never reused. Removing content = `"deprecated": true`.

## 3. Examples (illustrative)

### world/areas/verdant_hollow.json
Engine area (fields: [world-model §2](../engine/world-model.md#2-content-schema-engine-part)); the RPG "conquest" is the
area completion rule, the mandatory boss a game predicate in `completion.required`.
```json
{
  "id": "area:verdant_hollow",
  "kind": "explorable",
  "startLocation": "loc:verdant_hollow.portal_clearing",
  "locations": ["loc:verdant_hollow.portal_clearing", "loc:verdant_hollow.old_well", "loc:verdant_hollow.well_bottom"],
  "completion": {
    "pool": { "tag": "ordinary" },
    "thresholdBp": 7000,
    "required": { "all": [{ "game": "defeated", "enemy": "enemy:hollow_matriarch" }] },
    "frozen": { "poolSize": 10, "requiredCount": 7, "at": "2026-12-01" }
  },
  "activities": ["idle:hunt", "idle:gather"]
}
```

### world/locations/verdant_hollow/old_well.json
Engine fields (`id`, `tags`, `exits`) plus RPG fields (illustrative; defined by the RPG schema).
```json
{
  "id": "loc:verdant_hollow.old_well",
  "tags": ["ordinary"],
  "scene": "scenes/verdant_hollow/old_well.tmj",
  "exits": [
    { "id": "exit:verdant_hollow.old_well_north", "to": "loc:verdant_hollow.portal_clearing" },
    {
      "id": "exit:verdant_hollow.old_well_down",
      "to": "loc:verdant_hollow.well_bottom",
      "requires": { "hasItem": { "item": "item:rope", "qty": 1 } }
    }
  ],
  "encounters": "enc:verdant_hollow.well",
  "resources": [{ "node": "res:glowcap", "lootTable": "loot:glowcap_gather" }],
  "hotspots": [{ "id": "inscription", "type": "lore", "textKey": "lore.old_well.inscription" }]
}
```

Hotspot/exit **geometry** lives in the Tiled `.tmj` (object name = hotspot/exit ID); gameplay data lives in JSON. The
compiler checks both sides match.

### skill.json
```json
{
  "id": "skill:shield_bash",
  "cooldownTicks": 8,
  "windupTicks": 0,
  "targeting": "enemy",
  "effects": [
    { "type": "damage", "coeffBp": 8000, "school": "physical" },
    { "type": "taunt", "duration": { "value": 3, "unit": "attacks" } }
  ]
}
```

## 4. Compiler (`engine/content-compiler`, CLI `content-cli`)

Usage, plugin interface, error codes and bundle format: [`engine/content-compiler/README.md`](../../engine/content-compiler/README.md).

Commands: `validate <root> --game <plugin>`, `build <root> --game <plugin> --out <file> [--previous <bundle>]`
(→ bundle + `contentHash`, SHA-256 of canonical JSON), `graph <root> --game <plugin> [--area <id>]` (Mermaid),
`schema --game <plugin>` (JSON Schema export).

Checks:
- Zod schema per file (engine world schemas + game schemas/extensions), ID namespace per collection, duplicate IDs.
- Referential integrity: world references (`@engine/world` validation) and every reference the game plugin declares.
- World graph ([world-model §7](../engine/world-model.md#7-validation-content-compiler)): every area reachable from a
  hub; all locations reachable from `startLocation`; ≥ `requiredCount` pool locations reachable without `secret`
  exits; requirement predicates and their arguments; mandatory bosses etc. via the game's `validate` hook.
- Frozen completion baseline unchanged versus the previous published bundle (`--previous`): same `frozen` values, no
  published pool location removed or untagged.
- *Planned:* Tiled ↔ JSON consistency (every exit/hotspot has geometry and vice versa); art budget (background
  dimensions and compressed size within limits, from spike 2).

## 5. Localization

User-facing strings referenced by keys (`textKey`) in `content/i18n/<lang>.json`; English first.
