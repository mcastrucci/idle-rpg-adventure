# Spec: Shared Combat Engine

> Status: **Draft v0.1** — formulas and numbers are *provisional* until spike 1 and the M1 balance pass.
> Decisions: [ADR-0003](../adr/0003-simulation-server-only.md), [ADR-0004](../adr/0004-deterministic-step-engine.md),
> [ADR-0013](../adr/0013-tick-and-idle-encounter-model.md).

> **Location (ADR-0017):** `games/rpg/packages/rpg-sim`, built on `engine/sim-core` (RNG, integer math). It serves the
> engine's `EncounterHandler` (live) and `ExpeditionSimulator` (idle) plugin interfaces.

## 1. Interface

```ts
// packages/sim — illustrative signatures, not final code
createCombat(setup: CombatSetup, seed: Seed): CombatState
step(state: CombatState, inputs: Input[], rng: RngStreams): { state: CombatState; events: CombatEvent[] }
isFinished(state: CombatState): CombatOutcome | null
// helpers
runToEnd(setup, seed, policy): { outcome, events }     // idle & balance tools
```

- `inputs` are applied at the start of the tick in which they are received (live) or generated by `policy` (idle).
- The engine never reads the clock or does I/O.

## 2. Tick

- Tick = **500 ms** *(provisional)*; only meaningful in live for pacing. Idle runs ticks as fast as possible.
- Order within a tick:
  1. Apply inputs (queue manual actions; toggles).
  2. Process periodic effects (DoT/HoT) in effect-application order.
  3. Determine ready actors (action timer reached 0), sorted by `initiative desc, actorId asc`.
  4. For each ready actor: choose action (queued manual input → automation rules → enemy AI), resolve it fully, emit
     events. Windup actions emit `TelegraphStarted` and resolve after `windupTicks`.
  5. Decrement durations measured in ticks; expire effects.
  6. Check end conditions (all enemies dead → victory; all heroes dead → defeat).

## 3. Stats (provisional)

Attributes: `STR`, `AGI`, `INT`, `VIT`, `SPI`. Derived (integers):

| Stat | Source |
|---|---|
| `maxHp` | base + VIT × k + gear |
| `power` | max(STR, INT)-based per skill school + gear |
| `armor`, `resist` | gear + VIT/SPI |
| `critBp` | AGI-based, basis points |
| `haste` | reduces action interval in ticks (floor 2 ticks) |
| `healPower` | SPI-based |

## 4. Formulas (provisional, integer-only)

```
raw       = power * skillCoeffBp / 10000
mitigated = raw * 10000 / (10000 + armor * ARMOR_K)          // integer division, floor
crit      = rng.combat.bp() < critBp ? mitigated * CRIT_MULT_BP / 10000 : mitigated
final     = max(1, crit)
```

All divisions floor. No floating point, no `Math.pow/exp/log`. Curves (e.g. XP to level) come from precomputed tables in
content.

## 5. Effects and durations

Each effect declares a **duration unit**:

| Unit | Consumed by |
|---|---|
| `ticks` | global tick counter |
| `actions` | each action performed by the **effect owner** |
| `attacks` | each **eligible attack** (e.g. taunt: attacks by the taunted enemy) |

Example: `taunt { charges: 3, unit: "attacks" }` forces the target to attack the taunter for its next 3 attacks.

## 6. Automation rules

Ordered list evaluated top-down when the actor is ready and has no queued manual action. First matching rule fires.

```json
[
  { "when": { "selfHpBelowBp": 3500 }, "do": { "useConsumable": "item:minor_healing_potion" } },
  { "when": { "enemyTelegraphing": true, "skillReady": "skill:guard" }, "do": { "useSkill": "skill:guard" } },
  { "when": { "allyHpBelowBp": 5000, "skillReady": "skill:mend" }, "do": { "useSkill": "skill:mend", "target": "lowestHpAlly" } },
  { "when": { "skillReady": "skill:cleave", "enemiesAtLeast": 2 }, "do": { "useSkill": "skill:cleave" } },
  { "when": {}, "do": { "useSkill": "skill:basic_attack", "target": "lowestHpEnemy" } }
]
```

- Conditions and actions are a closed set (validated by Zod).
- Rule slots limited *(provisional: 6)*.
- Same rules drive live auto mode, disconnected participants and idle.

## 7. Enemy AI

Declarative behaviours: priority list like automation rules, plus boss scripts as **phase tables** (HP thresholds →
skill rotation, telegraphs). Bosses must have at least one mechanic that rewards a manual response in live (e.g. a
telegraphed heavy strike countered by `guard`), while being survivable by good automation rules in idle.

## 8. RNG

- PCG32 (or equivalent 32-bit integer PRNG via `Math.imul`).
- Root seed per combat/expedition; named streams derived by hashing `(rootSeed, streamName)`:
  `combat`, `loot`, `encounters`, `ai`.
- RNG state is part of `CombatState` (serializable for checkpoints).

## 9. Events

Typed, append-only, used for rendering (live), reports (idle), death logs and tests:
`CombatStarted`, `ActionStarted`, `TelegraphStarted`, `DamageDealt`, `Healed`, `EffectApplied`, `EffectExpired`,
`ConsumableUsed`, `ActorDied`, `PhaseChanged`, `CombatEnded`.

## 10. Versioning and tests

- `ENGINE_VERSION` constant; any behavioural change bumps it.
- Golden replay fixtures: `(setup, seed, inputs) → hash(events)`; CI runs them on two Node LTS versions.
- Property tests: no negative HP, ended combats stay ended, determinism (run twice ⇒ same hash).
